# 工程边界与维护

`web/src/app` 管路由与 SEO，`web/src/components` 管页面组件，`web/src/styles` 按公共站、账户、检测和后台组织样式。公开内容由 Next.js 服务端读取，账户和后台交互通过同源 `/api/v1/` 请求 Python。

`api/app/catalog.py` 是后台功能契约，基于 `shared/catalog.json` 整理字段、菜单与操作。前后端共用配置，服务端仍独立检查权限、参数和数据归属。修改模块先改契约，再修改专用业务；不要在页面中添加临时角色判断来代替 API 权限。

## 数据

- PostgreSQL 为生产目标数据库。SQLAlchemy 管关系和事务，Alembic 管版本；本地显式选择 SQLite。
- 身份、角色、会话、积分钱包、积分流水、加密凭证、执行任务、报告、流量、审计为关系表。
- 站点、分类、公告、报价、文章、广告、订单、积分权益等使用 `records` 表和模块 JSON；重要状态迁移仍经专用服务处理。
- 站点快照是 2026-11-12 的来源资料，不标成当前实测。原始政策和分组报价保留；无统一价格时不参与计算。
- 积分流水使用用户与业务事件唯一约束，余额通过条件更新扣减；兑换失败时整个事务回滚。

## 认证与权限

密码使用 scrypt；会话 token 只在 HttpOnly Cookie，数据库只保留哈希。写操作校验 CSRF 与来源。RBAC 包含功能读取、操作权限与本人/全部数据范围，菜单显隐不等于授权。站长只能管理自己的推广内容和对应流量。

API Key 用 Fernet 加密，模型列表从所选 Key 和协议获取。密钥不返回浏览器，不进入分享证据。修改加密主密钥前需要迁移密文，不能直接替换环境变量。检测目标拒绝内网、元数据地址和重定向，并固定域名解析后的目标 IP。

## 队列

`python -m app.worker` 独立运行：检查定时计划、原子领取执行任务、有界并行请求、保存证据、处理告警、刷新缓存。PostgreSQL 使用行锁和 `skip locked`，SQLite 使用条件状态更新。定时触发带去重键，间隔、每日时间和五位 Cron 支持北京时间/UTC。

取消会阻止后续项目并清除临时凭证，已经发出的单次 HTTP 请求等待超时结束。长时间失联任务标记失败，重试会新建执行记录，保留历史证据。

糖果测试是 5 题固定题集；分数为正确题数 / 5 × 100。模型指纹使用三题数字样本的 14 维特征、可信模型基线和独立样本校准；API 模式仅对照同协议基线。距离超限、缺少对照或候选过近时返回未知，相似度不是身份概率。

## 发布与 SEO

稳定路径使用语义 slug。修改站名、描述和政策不会改变 URL。修改站点 slug 会保存旧地址，Next.js 返回 301，历史别名直接指向最新地址。公开目录、详情、分类、模型和内容有 HTML、title、description、canonical、OG 与适用的结构化数据。

公开内容修改与缓存失效事件同事务写入。API 尝试通知 Next.js；失败的事件由 worker 重试。`revalidateTag(..., {expire: 0})` 让下一次访问取得新数据，无需全站重新构建。当前部署按单个 Next 实例设计；扩容时须共享缓存或广播失效事件。

管理、账户、筛选组合和私人报告按规则 noindex。robots 不代替会话认证。sitemap 从已公开数据读取；404 不伪装为成功页面。

## 推广与统计

广告提交 → 平台审核 → 站长生成订单 → 平台核对实际付款 → 投放期展示。支付确认需要独立权限；未接支付网关，不把点击付款当成支付成功。没有发票申请模块。

浏览器采集 PV、匿名访客、停留、来源域名、设备、官网跳转、广告曝光和点击。曝光使用可见性观察；事件 ID 防重复。UV 是按月匿名标识去重，不等同于自然人数，也不根据 IP 猜测地区。检测趋势单独根据真实报告计算。
