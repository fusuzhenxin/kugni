# 前台中英文本地化

中文继续使用原路径，英文使用 `/en/`，例如 `/models/openai/` 与 `/en/models/openai/`。语言按钮保留当前页面和查询参数，不按 IP 强制跳转。后台保持中文，管理入口 `/admin/content/translations/` 遵循现有 RBAC，站长账号不能访问。

## 发布流程

1. 保存、发布中文资料时，在同一事务内建立翻译槽，只记录变化的公开字段；请求期间不调用翻译服务。
2. 已有界面和资料使用 `shared/locales/en.json` 中的英文。新句子由独立后台翻译线程逐条处理，翻译结果保存在数据库。
3. 成功后通过现有缓存失效 outbox 更新前端；无需站长手动构建、复制页面或重新发布中文。
4. 人工编辑的译文受保护；中文再次变化后进入“待校对”，不会被自动任务覆盖。后台提供查看、编辑和批量重试，并记录审计。

翻译记录保存来源字段、中文哈希、译文哈希和版本号。任务领取使用版本条件；中文改变、记录删除、人工修改后，旧请求不能覆盖新版本。草稿、撤下记录不进入公开翻译包。只允许翻译明确列出的公开资料字段，不翻译密钥、用户资料、评价、私有备注或原始检测证据。

## 免费通道的边界

当前由开源 HTTPX 适配免 Key Google 网页翻译通道。开源的是适配程序，翻译仍由站外服务提供，不是本机的开源模型。不购买 API、不部署模型、不需要 GPU。此前 deep-translator 网页适配遭遇限流的记录保留为早期验收证据。

本轮已通过配置的采集代理真实连通免费通道，处理旧积压并完成3,591条公开翻译记录。相同原文去重、小批量请求、链接与代码保护和质量检查已接通；免费上游仍可能限流或变化，不能承诺长期可用。中文发布不等待翻译。最新处理入口为 `/admin/content/translation-health/`；人工校对仍在原英文翻译模块。

任务单并发，每批最多16段、约2600字，长正文单独分段，子进程最多55秒。失败按5、10、20分钟等间隔退避，单条最多6次，相同失败原文共享退避；达到次数后保留翻译失败，可人工校对或批量重试。`TRANSLATION_ENABLED=false` 可暂停自动调用。可设置 `TRANSLATION_PROXY_URL`，留空时复用 `STATION_SOURCE_PROXY_URL`，无代理则直连，不读取系统代理；Compose支持这些配置。

## SEO

- 页面正文和元信息在服务端生成，禁用 JavaScript 仍可阅读英文。
- 中文、英文使用各自 canonical；英文完成时输出双向 `hreflang=zh-CN/en` 和中文 `x-default`。
- `<html lang>`、标题、描述、关键词、Open Graph 和结构化数据按语言输出。
- 英文正文或元信息缺译、译文版本过期时暂设 `noindex`，不加入 sitemap。中文发布和中文索引不等待英文任务。
- 搜索筛选、登录、个人中心、私有报告等仍不可索引；站点改路径的 301 保留语言。
- 指纹测试题目、原始回答和执行证据保留原文，不因界面语言改变模型请求或复制内容。

这些措施规范技术输出，不等于搜索引擎保证收录或排名。正式域名上线后仍需提交 sitemap 并检查搜索引擎抓取结果。

## 维护与服务器

`shared/locales/en.json` 是内置英文的唯一维护源；`node scripts/export-locale-sources.mjs` 从本地 API 抽取界面句子并写入 `shared/locales/sources.json`，覆盖检查输出到 `verification/locale-coverage.json`。改内置词典后需重新构建前端；站点资料的日常修改不需要构建。启动 seed 会幂等同步翻译槽，不覆盖人工校对。

前后端共用词典，因此 Next.js 构建根目录覆盖本工程；生产 standalone 入口为 `web/.next/standalone/web/server.js`，本地启动脚本和 Dockerfile 均已对应调整。

增加的运行负担是数据库中的文字、单并发低频任务及短暂翻译子进程。小流量整站部署可从 2 核 4 GB 内存起步，不因双语单独加 GPU；这不是压力测试结论。高并发检测、大量定时计划和访问增长需按实测扩容，生产构建建议在 CI 或内存更充足的机器进行。

验证命令：Python 测试、`node --test scripts/test-localization.mjs`、前端类型/格式/生产构建、`npm run test:e2e`。浏览器测试仅使用临时站点和明确的报告夹具，结束后清理，不发布假检测分数。
