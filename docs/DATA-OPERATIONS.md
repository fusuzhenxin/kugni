# 模型报价、采集健康、英文与 SEO 运维

本轮按站主确认实现五项功能。采集健康不增加站内消息、邮件或 Webhook 通知；保留原检测告警模块的既有行为。

## 模型与报价自动更新

入口：管理后台 → 数据采集 → 站点公告与渠道采集。原任务可勾选「模型与报价」，与公告、渠道共享已有北京时间调度；支持手动运行与批量运行。保存与执行均检查任务运行权限、关联站点编辑权限。来源代码在 `api/app/station_pricing.py`。

已实跑的九家：0elog、7Code、8sToken、AruHub、MNAPI、球球Token、酸奶AI、兔子API、ZetaTechs。沿用原每日时间。共 3,477 条精确型号与分组报价；这是多站累计记录，不代表 3,477 款独立模型。

- New API 标准 `/api/pricing`：型号、启用分组、分组倍率、模型倍率、输出倍率、缓存读写倍率、按次单价、协议与动态计费规则。
- MNAPI 的 `group_info` / `model_info` / `price_info` 结构单独规范化。保留分组规则，不把其不同的计费枚举直接套用为标准按次计费。
- 默认币种未确认。只有核实币种并填写「1倍率每百万Token基准单价」后，简单计费才换算金额。零值、缺失值区分；阶梯表达式不执行、不用简单倍率估算。完整规则按哈希去重保存在数据库，前台提供来源链接。
- 空目录、重复型号/分组、格式异常或请求失败保留上次数据。人工维护的站点资料、生态筛选与标准报价不被采集覆盖。发现的精确型号单独保存在 `sourceModelIds`，模型数量与报价时间自动更新。
- 站点改路径时同步报价关联，并沿用真实 301；刷新 Next.js 页面缓存。列表只返回展示所需的报价单元格，站点接口保留规范化依据，避免全部报价超过 Next.js 的 2 MB 缓存限制。
- 当前非标准/需要登录的其他报价来源未自动宣称接通。健康面板区分初始快照和已自动同步资料。

## 采集健康与渠道核查

入口：`/admin/collection/health/`、`/admin/collection/sources/`。平台全站数据范围与独立权限控制，站长账户不能访问。查看覆盖数、报价与型号数量、最新采集、下次执行、快照过期、调度延迟、连续失败、分项错误、警告和最近运行。

20 家站点均有渠道来源核查记录，记录来源、范围、核查日期和未接入原因。aigocode 继续按站主要求跳过；Foxcode 和 AICodeMirror 的访问验证未绕过、未反复登录。未发现公开接口不等于该站不存在监控。

新补智流 FluxLane：官网脚本直接引用 `/fluxlane-home/success-week.json`，七个北京时间日统计及最多三款型号的周汇总。全站历史不分配给具体上游分组，型号周汇总不伪造按日历史或实时心跳。当前 9 家有来源状态、6 家有带时间的历史，AruHub 另提供无逐条时间戳的近期调用记录。

## 英文完成度与免费翻译

入口：`/admin/content/translation-health/`，译文编辑仍在 `/admin/content/translations/`。

后台按相同原文去重、复用完成的译文，单线程小批量处理；优先界面、站点、分类与 SEO 内容。每条有版本与哈希保护，中文更新、删除或人工校对后，迟到结果不能覆盖。相同失败原文共享退避，避免换一条重复记录就再次请求。链接和行内代码使用经过校验的占位符保留，拒绝残留中文或改变链接的译文；人工译文不自动覆盖。

使用固定的免费 Google 网页翻译通道，不需要付费 API Key 或部署模型。调用代码使用开源 HTTPX；这不意味着站外翻译引擎本身开源，也不承诺上游长期可用。超时/限流时退避；中文继续发布，未完成英文维持 noindex。可配置 `TRANSLATION_PROXY_URL`，留空时复用 `STATION_SOURCE_PROXY_URL`，都不配置则直连；不读取系统代理。部署时需使用服务器可达的网络出口。

本轮已有英文积压已处理；初始完成记录为 3,591 条，后续会随资料变化自动增加。该数量是文字记录，不是页面数。新增模型的中文名称、必要标签和缺失英文描述也进入队列，已有原生英文描述直接使用。套餐英文页面按实际正文与元信息完成度开放收录，缺译占位文案不冒充完整英文。大页数分页与图标首字母也已统一处理。

## SEO 巡检与复检

入口：`/admin/content/seo-inspections/`、`/admin/content/seo-inspection-runs/`、`/admin/content/seo-issues/`。已有每日北京时间 06:20 计划，可编辑语言、页面上限、站内链接与时间。通过 worker 读取实际 SSR HTML，首次站点地图允许更长加载时间。每批最多三个并发 HTTP 读取，解析与落库受界限控制。

检查 HTTP 状态、标题与描述、H1、正式 canonical、HTML 语言、hreflang、Open Graph、JSON-LD、重复标题/描述与站内断链。只读取配置的本站前端与公开路径，不抓管理端、登录、私有报告或任意外部目标。链接的站内跳转有循环/跨站/次数检查。

全站任务按页面上限轮换，明确记录发现页数、本轮页数、完成数、链接数量与跳过上限；不会把抽样标成全站通过。首次完整基线检查了 1,480 页与 218 个站内链接目标，发现的问题已用于实际修复：英文完整性漏判、重复元信息及开发者页 `/about.md` 断链。

基线发现355条问题。修复后，通过后台正常批量复检动作完成四批、428次页面检查与216次链接目标检查（各批可能重复检查同一页面或链接），四批均未发现问题，当前待处理为0。证据为 `verification/data-seo-rechecks.json`；完整覆盖、报价计数、译文状态与中英文SSR核验为 `verification/data-operations-release.json`。

问题按任务、页面与规则去重。支持单条与批量「复检」，只检查有关页面；重复元信息会同时检查对照页。复检不移动全站轮换位置；只把真正复查且不再出现的问题标为已恢复，不把其他未检查页面一并清除。任务排队/执行、防重复、分批租约、失联恢复和执行时再次校验用户权限均已接入。

巡检确认的是本站技术输出，不代表 Google/Bing 已抓取、收录或给予排名。生产域名、HTTPS、数据库与搜索平台实际抓取仍按部署流程验收。
